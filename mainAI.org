* Automi e segnali
In questa documentazione, descriviamo un programma scritto in \textbf{Go} (Golang) per gestire automi su un piano 2D con ostacoli rettangolari. L’obiettivo è fornire un prototipo funzionante di simulazione in cui l’utente, tramite riga di comando, può:
- Creare (o ricreare) un “piano” rappresentante l’ambiente.
- Aggiungere o spostare automi in specifiche coordinate.
- Inserire ostacoli e verificare la presenza di percorsi liberi.
- Controllare lo stato di una data cella.

Le scelte di implementazione privilegiano la semplicità e l’uso di colonne dati basilari (\verb|map|, \verb|slice|, \verb|struct|). Tuttavia, discutiamo anche di possibili generalizzazioni e di analisi della complessità (tempo e spazio) per ogni funzione principale.

** Backbone
Qui presentiamo le definizioni fondamentali del programma. Non vengono utilizzate librerie esterne oltre a quelle standard di Go. Tale scelta minimizza le dipendenze esterne e favorisce la portabilità, benché talvolta librerie esterne possano offrire funzioni di pathfinding più efficienti (vedi sezione di \emph{Possibili miglioramenti}).

```go
package main

import (
    "bufio"
    "fmt"
    "os"
    "strconv"
    "strings"
)

// punto rappresenta una posizione nella griglia 2D
type punto struct {
    x, y int
}

// automa rappresenta un singolo automa
type automa = punto

// ostacolo rappresenta un ostacolo rettangolare
type ostacolo struct {
    angoloInferioreSinistro punto
    angoloSuperioreDestro   punto
}

// piano rappresenta l'intero sistema, includendo automi e ostacoli
type piano struct {
    automi            map[string]automa
    ostacoli          []ostacolo
    daReinizializzare *bool
}

func main() {
    p := newPiano()

    reader := bufio.NewReader(os.Stdin)
    for {
        // Se richiesto dal comando 'c', si ricrea un nuovo piano
        if *p.daReinizializzare {
            p = newPiano()
            *p.daReinizializzare = false
        }
        fmt.Print("Enter command: ")
        riga, _ := reader.ReadString('\n')
        esegui(riga, p)
    }
}
```

** Spiegazione e analisi del problema
Il problema consiste nel gestire un piano 2D (potenzialmente illimitato) con un insieme di automi e ostacoli. Ogni cella del piano è caratterizzata da:
- La possibile presenza di un automa.
- L’inclusione in uno (o più) ostacoli rettangolari.
- Essere vuota.

L’interfaccia testuale permette all’utente di:
1. Inserire, rimuovere, o spostare automi (identificati da un nome).
2. Inserire ostacoli rettangolari.
3. Verificare percorsi liberi usando una tecnica di \emph{ricerca} (discussa nella sezione dedicata).
4. Stampare lo stato di un singolo punto o di tutti gli oggetti presenti.

Dal punto di vista della complessità, la struttura dati centrale è costituita da:
- Una \verb|map[string]automa| per memorizzare i nomi degli automi e le loro coordinate.
- Una slice di ostacoli, ciascuno definito da due punti.

Questa scelta offre un buon compromesso tra semplicità e immediatezza:
- Gli accessi alla mappa (\verb|automi|) avvengono in \(\mathbf{O}(1)\) \emph{amortizzato} per l’inserimento, la ricerca e l’aggiornamento.
- L’inserimento degli ostacoli in una slice ha complessità \(\mathbf{O}(1)\) \emph{amortizzato}.

La verifica dell’esistenza di un automa in un punto deve iterare sulla mappa se ci fosse necessità di scorrere tutti i valore; tuttavia, la maggior parte delle funzioni (e.g., \verb|esegui|) individua un automa direttamente per nome, riducendo quindi il costo a \(\mathbf{O}(1)\). Viceversa, controllare se un punto sia in un ostacolo richiede \(\mathbf{O}(n)\) dove \(n\) è il numero di ostacoli, giacché occorre verificare ogni rettangolo per vedere se contiene il punto.

Dal punto di vista \emph{spaziale}, i principali costi di memoria risiedono nei container \verb|map| e \verb|slice|, che crescono a seconda del numero di automi e ostacoli.

*** Definizioni
1. \verb|punto|: semplice coppia \verb|(x, y)| di interi, che definisce una posizione su una griglia.
2. \verb|automa|: alias di \verb|punto|, usato per sottolineare la differenza semantica rispetto a un generico punto.
3. \verb|ostacolo|: definisce un rettangolo sull’asse x-y tramite due punti estremi.
4. \verb|piano|: raccoglie \verb|automi| e \verb|ostacoli|, oltre a un flag booleano per la re-inizializzazione.

**** Esegui
```go
func esegui(s string, p piano) {
    parti := strings.Fields(s)
    comando := parti[0][0]

    switch comando {
    case 'c':
        *p.daReinizializzare = true
    case 'S':
        p.stampaTutto()
    case 's':
        a, _ := strconv.Atoi(parti[1])
        b, _ := strconv.Atoi(parti[2])
        p.stampaStato(a, b)
    case 'a':
        a, _ := strconv.Atoi(parti[1])
        b, _ := strconv.Atoi(parti[2])
        omega := parti[3]
        p.aggiungiAutoma(a, b, omega)
    case 'o':
        a, _ := strconv.Atoi(parti[1])
        b, _ := strconv.Atoi(parti[2])
        c, _ := strconv.Atoi(parti[3])
        d, _ := strconv.Atoi(parti[4])
        p.aggiungiOstacolo(a, b, c, d)
    case 'r':
        // Eventuale richiamo
    case 'p':
        omega := parti[1]
        p.stampaAutomi(omega)
    case 'e':
        x, _ := strconv.Atoi(parti[1])
        y, _ := strconv.Atoi(parti[2])
        nome := parti[3]
        p.stampaEsistenzaPercorso(x, y, nome)
    case 'f':
        os.Exit(0)
    }
}
```
\textbf{Analisi}: \(\mathbf{O}(m)\) dove \(m\) è il numero di token nella riga di comando. Ogni operazione interna ha costi che dipendono dalle funzioni che esegue (vedi \verb|stampaStato|, \verb|aggiungiAutoma|, \ldots).

**** Stato
```go
// Stato stampa cosa c'è nella posizione data
func (p *piano) stampaStato(x, y int) {
    punto := punto{x: x, y: y}

    // Controlla se il punto è in un ostacolo
    if p.verificaPuntoInOstacolo(punto) {
        fmt.Println("O")
        return
    }

    // Controlla se il punto contiene un automa
    if p.verificaPuntoAutoma(punto) {
        fmt.Println("A")
        return
    }

    // Se nessuna delle condizioni precedenti è soddisfatta, il punto è vuoto
    fmt.Println("E")
}
```
\textbf{Analisi}:
- \verb|verificaPuntoInOstacolo|: \(\mathbf{O}(n)\) con \(n\) = numero di ostacoli.
- \verb|verificaPuntoAutoma|: potenzialmente \(\mathbf{O}(k)\) se occorre scorrere tutti gli automi, dove \(k\) è il numero di automi (ma spesso ci si può fermare appena ne troviamo uno).
Il tempo complessivo è dunque \(\mathbf{O}(n + k)\) nel peggiore dei casi.

func (p *piano) stampaTutto() {

**** Ostacolo
```go
// Ostacolo aggiunge un ostacolo se possibile
func (p *piano) aggiungiOstacolo(x0, y0, x1, y1 int) {

    ostacolo := ostacolo{
        angoloInferioreSinistro: punto{x: x0, y: y0},
        angoloSuperioreDestro:   punto{x: x1, y: y1},
    }

    // Controlla se un automa è nell'area proposta per l'ostacolo
    if p.verificaAutomaInOstacolo(ostacolo) {
        return
    }

    // Aggiungi ostacolo
    p.ostacoli = append(p.ostacoli, ostacolo)
}
```
\textbf{Analisi}:
- \verb|verificaAutomaInOstacolo| scorre i valori nella mappa di automi per controllare se qualche automa rientra nei limiti dell’ostacolo (\(\mathbf{O}(k)\) con \(k\) = numero di automi).
- L’append allo slice di ostacoli è \(\mathbf{O}(1)\) \emph{amortizzato}.
- Complessivamente \(\mathbf{O}(k)\).

**** Richiamo

```go
// Calcolo della calcolaDistanzaManhattan di Manhattan
func calcolaDistanzaManhattan(a, b punto) int {
    return valoreAssoluto(b.x - a.x) + valoreAssoluto(b.y - a.y)
}

func valoreAssoluto(x int) int {
    if x < 0 {
        return -x
    }
    return x
}

// verificaPrefisso controlla se α è un prefisso di η
func verificaPrefisso(alpha, eta string) bool {
    if len(alpha) > len(eta) {
        return false
    }
    return eta[:len(alpha)] == alpha
}

func (p *piano) filtraAutomiPerPrefisso(alpha string) []automa {
    automiFiltrati := make([]automa, 0)
    for nome, automa := range p.automi {
        if verificaPrefisso(alpha, nome) {
            automiFiltrati = append(automiFiltrati, automa)
        }
    }
    return automiFiltrati
}

// Richiamo emette un segnale dal punto (x,y)
func (p *piano) emettiRichiamo(x, y int, alpha string) {
    sorgente := punto{x: x, y: y}

    // Se la sorgente è in un ostacolo, nessun movimento possibile
    if p.verificaPuntoInOstacolo(sorgente) {
        return
    }

    for _, automa := range p.filtraAutomiPerPrefisso(alpha) {
        // Se esiste un percorso libero, l’automa tende a spostarsi
        if p.esistePercorsoMinimoLibero(sorgente, automa) {
            automa.x = sorgente.x
            automa.y = sorgente.y
        }
    }
}
```
\textbf{Analisi}:
- \verb|filtraAutomiPerPrefisso|: \(\mathbf{O}(k)\).
- Ogni chiamata a \verb|p.esistePercorsoMinimoLibero| potrebbe avere costo significativo (vedi sezione successiva).
- Complessità finale dipende dal numero di automi filtrati e dall’implementazione di \verb|esistePercorsoMinimoLibero|.

**** Esiste Percorso
La parte che segue mostra una versione semplice di \emph{ricerca del percorso}, basata sul confrontare la \emph{Manhattan distance} e muoversi in direzioni che riducono tale distanza. Codice riportato per completezza:

```go
// EsistePercorso controlla se esiste un percorso libero
func (p *piano) stampaEsistenzaPercorso(x, y int, nome string) {
    dest := punto{x: x, y: y}

    // Controlla se l'automa esiste e se la destinazione è valida
    aut, esiste := p.automi[nome]

    if !esiste || p.verificaPuntoInOstacolo(dest) {
        fmt.Println("NO")
        return
    }

    if p.esistePercorsoMinimoLibero(aut, dest) {
        fmt.Println("SI")
    } else {
        fmt.Println("NO")
    }
}

// trovaPassiUnitariAmmessi returns the immediate direction from current to target.
func trovaPassiUnitariAmmessi(da, a punto) [][2]int {
    passiUnitariAmmessi := [][2]int{}

    if a.x > da.x {
        passiUnitariAmmessi = append(passiUnitariAmmessi, [2]int{1, 0})
    } else if a.x < da.x {
        passiUnitariAmmessi = append(passiUnitariAmmessi, [2]int{-1, 0})
    }

    if a.y > da.y {
        passiUnitariAmmessi = append(passiUnitariAmmessi, [2]int{0, 1})
    } else if a.y < da.y {
        passiUnitariAmmessi = append(passiUnitariAmmessi, [2]int{0, -1})
    }

    return passiUnitariAmmessi
}

// esistePercorsoMinimoLibero controlla se esiste un percorso libero di lunghezza minima
func (p *piano) esistePercorsoMinimoLibero(aut automa, dest punto) bool {

    direzioni := trovaPassiUnitariAmmessi(aut, dest)

    // Initialize queue with the starting point
    queue := []punto{aut}

    for len(queue) > 0 {
        current := queue[0]
        queue = queue[1:]

        // Se abbiamo raggiunto il target
        if current == dest {
            return true
        }

        // Espansione in base alle direzioni “ammesse”
        for _, dir := range direzioni {
            prossimoPunto := punto{
                x: current.x + dir[0],
                y: current.y + dir[1],
            }

            // Se muoversi riduce la distanza Manhattan e l’area NON è occupata, accodiamo
            if calcolaDistanzaManhattan(prossimoPunto, dest) < calcolaDistanzaManhattan(current, dest) &&
               !p.verificaPuntoInOstacolo(prossimoPunto) {
                queue = append(queue, prossimoPunto)
            }
        }
    }
    return false
}
```
\textbf{Analisi}:
- La coda \verb|queue| gestisce un certo \emph{numero} di punti da esplorare. In questo approccio l’esplorazione è limitata solo a mosse che decrementano la \emph{Manhattan distance}, quindi la lunghezza massima del percorso è dell’ordine di \(\lvert x_{\mathrm{start}} - x_{\mathrm{dest}} \rvert + \lvert y_{\mathrm{start}} - y_{\mathrm{dest}} \rvert\). 
- In casi peggiori, la complessità può essere \(\mathbf{O}(d)\), dove \(d\) è la distanza Manhattan fra partenza e destinazione, considerando che ogni passo limita la ricerca. Se la griglia fosse molto ampia e presenti molti ostacoli, questa strategia potrebbe \emph{fallire} nel trovare percorsi che richiedono movimenti temporaneamente “lontano” dal target.

** Possibili miglioramenti:
- \textbf{BFS o A*}: L’uso di BFS (Breadth-First Search) o A* su una griglia discreta (magari con coordinate limitate) consentirebbe di trovare percorsi validi più elaborati, ma servirebbe una struttura di dati per segnare celle visitate, con un costo potenziale maggiore in termini di memoria e complessità temporale \(\mathbf{O}(\ell)\), dove \(\ell\) è il numero di celle effettivamente esplorate nel \emph{worst case}.
- \textbf{Alberi di segmenti o strutture spaziali}: se servisse verificare collisioni ostacolo-punto su grandi insiemi di rettangoli, ci si potrebbe affidare a strutture quali \emph{segment trees}, \emph{interval trees} o \emph{R-trees} per abbassare i costi di query.
- \textbf{Evitare un eccesso di controlli ripetuti}: in alcune situazioni, conviene \emph{caching} di certe informazioni (ad es. la presenza di un ostacolo in una data posizione), a scapito di un utilizzo di memoria aggiuntivo.

*** Utilities
In questa sezione troviamo funzioni di supporto utili per semplificare lo sviluppo:

```go
// verificaPuntoInOstacolo controlla se un punto è dentro un ostacolo
func (p *piano) verificaPuntoInOstacolo(punto punto) bool {
    for _, ost := range p.ostacoli {
        if punto.x >= ost.angoloInferioreSinistro.x && punto.x <= ost.angoloSuperioreDestro.x &&
           punto.y >= ost.angoloInferioreSinistro.y && punto.y <= ost.angoloSuperioreDestro.y {
            return true
        }
    }
    return false
}

// verificaPuntoAutoma checks if a point is an automaton
func (p *piano) verificaPuntoAutoma(punto punto) bool {
    for _, aut := range p.automi {
        if aut == punto {
            return true
        }
    }
    return false
}

// verificaAutomaInOstacolo checks if there is any automaton within the given obstacle
func (p *piano) verificaAutomaInOstacolo(ostacolo ostacolo) bool {
    for _, aut := range p.automi {
        if aut.x >= ostacolo.angoloInferioreSinistro.x && aut.x <= ostacolo.angoloSuperioreDestro.x &&
           aut.y >= ostacolo.angoloInferioreSinistro.y && aut.y <= ostacolo.angoloSuperioreDestro.y {
            return true
        }
    }
    return false
}
```
\textbf{Analisi}:
- Ognuna di queste funzioni scorre linearmente i rispettivi container (\verb|p.ostacoli| o \verb|p.automi|). Ciò comporta, in media, \(\mathbf{O}(n)\) o \(\mathbf{O}(k)\) a seconda del contesto (ostacoli vs. automi).
